# 战争进化史 · 微信小游戏

横屏 Canvas 原型，直接导入微信开发者工具。本项目使用小游戏入口 `game.js`，不需要 HTML、WXML、npm 安装或构建步骤。

## 导入与测试

1. 在微信开发者工具导入本仓库根目录（包含 `project.config.json`）。项目编译类型已设为 `game`。
2. 将项目 AppID 换成你自己的**微信小游戏 AppID**。仓库中的 `touristappid` 只是本地占位；若工具不支持游客模式，先填写有效 AppID。不要填普通小程序 AppID。
3. 编译运行后，选择简单／普通／困难，点击“开始对战”。模拟器使用横屏设备。
4. 点击卡片中的“生产”出兵，A／B 切换六种兵；“详情”查看定位。“防御塔”管理建造、升级和出售；技能冷却结束后点击战场选落点；经验达标点击进化。
5. 真机预览需要有效小游戏 AppID 和相应项目权限。重点检查横屏、胶囊安全区、触控、切后台和重新进入后的续局。

配置结构参考[微信官方小游戏示例](https://github.com/wechat-miniprogram/minigame-demo/blob/master/project.config.json)，查阅日期 2026-09-28。此处尚未实际运行微信开发者工具或真机，自动化检查不替代这一步。

## 本轮已实现

- 离线经典 PvE，三档 AI，五个时代和 30 兵种配置；AI 共用出兵、资源、人口及进化规则。
- 每时代六兵 A／B 分页，自动前进／索敌／交战，护甲克制、范围攻击、治疗、维修、光环、护盾等基础特性。
- 金币与经验收入、5 项生产队列、30 人口、取消退款；进化保留旧单位、已付款队列、塔和技能冷却。
- 三塔位、每时代两类塔、建造／升级／出售；技能落点选择、预警和伤害。
- 基地胜负、同一步同时摧毁判平局、20 分钟时限、暂停和重试。
- 每 5 秒及进入后台时保存本地 PvE 快照；重开游戏后“继续上次对战”恢复并保持暂停。快照只支持当前配置版本，损坏或旧版本不会恢复。存储不可用时提示并继续内存对局。
- 8 个可用兵种接入已有 Canva 透明预览图；未绘制及 4 个待重绘兵种使用明确占位图。当前图片不是正式动画资源。

## 当前边界与下一阶段

这是部分代码交付，不是设计文档中的完整首版。**15 关战役、通关记录、在线 PvP、匹配、好友房、服务端权威与断线重连尚未实现**，首页没有伪装成真人匹配的入口。最终首版验收仍要求 PvE 与 PvP 均可用。

当前战场完整显示单条路线，不支持拖动视野；详情用独立按钮打开，尚未做长按。远程伤害在攻击逻辑步结算，射线只作表现；动画、弹道飞行时间、音频、最终性能与平衡需要后续完善。暂停中的投降直接返回首页，尚无独立投降确认。HP、射程和伤害均为待验证初值。

Canva 后续素材仍归档到 `assets/units/ageN/unit_id/`；完成审核后运行 `python3 scripts/build-art-map.py` 更新本地索引。索引优先透明图，跳过 `revision_required` 条目，不改写原始图片。保留的 `assets/units/index.html` 仅为之前的素材清单，不是游戏预览，也不打包发布。

## 代码与验证

- `src/data.js`：版本化时代、兵种、克制初值。
- `src/battle.js`：不依赖微信 API 的固定步长模拟与合法指令入口；未来联网时还需服务端接管。
- `src/app.js`：微信生命周期、触控映射、本地存档、逻辑时钟。
- `src/renderer.js`：Canvas 场景、HUD、弹层及资源加载失败回退。
- `introduction/`：完整首版设计目标，与当前实现范围分开记录。

有 Node.js 环境时运行：

```sh
node --test tests/*.test.js
```

当前开发环境借用 VS Code 内置 Node 验证：

```sh
ELECTRON_RUN_AS_NODE=1 /usr/share/code/code --test tests/*.test.js
```

测试涵盖资源不足、队列与人口限制、退款、进化保留队列、跨时代伤害、治疗目标死亡、同时摧毁、技能预警、塔费用、时限、确定性恢复、完整 AI 模拟，以及模拟微信 API 的触控和生命周期。未验证真实微信基础库、网络能力或真机画面。
