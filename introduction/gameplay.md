### 1.2 本项目新增设计

本项目采用**五个时代、每时代六种兵，共 30 种单位**；加入 **PvP 在线实时 1v1** 与 **PvE 经典对战＋战役关卡**。这些模式扩展、兵种、克制关系及以下规则均为本项目设计，不是原作功能说明。

玩家负责生产、组合、防御投资、技能时机和时代进化，单位自动移动与交战。目标是用有限金币形成有效阵容，保护己方基地并突破敌方防线。兵种、美术、音效和 UI 使用原创设计，已有 15 个角色保留并扩展。

首版包含一个对称战场、30 种兵、五时代防御与技能、经典 AI 三档难度、15 个战役关卡、真人匹配与好友房。排位赛、商业化、无尽模式、多人混战、空战及局外战力养成留作后续扩展。

## 2. 模式入口与公共战场

### 2.1 微信小游戏入口

```text
小游戏首页
├─ PvE 单人
│  ├─ 经典对战 → 简单 / 普通 / 困难 → 战斗 → 结算
│  └─ 战役 → 章节 / 关卡 → 目标与敌情 → 战斗 → 结算
├─ PvP 对战
│  ├─ 真人匹配 → 搜索 → 双方准备 → 战斗 → 结算
│  └─ 好友房 → 创建 / 输入房间码 / 分享卡片进入 → 双方准备 → 战斗
├─ 兵种图鉴：可查看全部时代的定位、克制、攻击与支援方式
└─ 设置：声音、画质、操作说明
```

PvE 可先体验，战役按通关进度解锁。PvP 进入匹配或房间前建立玩家会话，身份验证失败显示重试入口。昵称、头像不作为开战必要条件。

### 2.2 战场与视角

```text
己方基地与塔位 → 己方前排 / 后排 → 交战区域 ← 敌军 ← 敌方基地与塔位
                         单一地面路线
```

- 双方各有一座基地；所有单位在基地前方出生并沿同一地面路线推进，不提供手动选兵、绕路或空中路线。
- 每位玩家看到自己的基地位于左侧。PvP 的左右镜像仅用于显示，双方共享同一权威战场坐标；触控技能落点需要转换为统一坐标。
- 基地 HP 归零通常结束对局；特殊战役目标和同时摧毁的规则见第 12 节。
- 同阵营单位允许逻辑穿行，显示时适度错位，避免前排被支援兵堵住；敌对地面单位不能穿越彼此。错位不形成额外路线或躲避能力。
- 战斗视野覆盖整条路线，允许拖动画面并一键回到己方基地。PvP 可见敌方单位、基地 HP、时代、塔位和技能预警；不公开敌方金币、EXP 与生产队列。

## 3. 公共资源与经济循环

**基础收入／交战 → 获得金币与 EXP → 出兵或建塔 → 调整组合 → 进化 → 推进 → 攻击基地。**

### 3.1 开局与初始数值

以下为**待验证的数值初值**，供原型和数值试算使用，不代表原作数值或已经通过平衡测试。调整应通过版本化配置进行，已开始的对局固定使用开局版本。

| 项目 | 经典对战与标准 PvP 初值 |
|---|---|
| 开始时代 | 原始时代，双方相同 |
| 初始金币 / 累计 EXP | 200 / 0 |
| 基地当前 / 最大 HP | 3000 / 3000，时代进化不改变或恢复基地 HP |
| 基础金币收入 | 每秒 8 × 当前时代费用系数 |
| 基础 EXP 收入 | 每秒 4，双方相同，保证不交战时也可进化 |
| 生产队列 / 人口上限 | 5 项（包含正在生产项）/ 30 人口 |
| 时代技能 | 开局进入完整冷却，初值 60 秒 |
| 标准 PvP 上限 | 15 分钟；这是模式规则，变更需同步界面和验收 |

金币可累计，不跨对局继承。战役可覆盖开始时代、初始资源与时限，但必须在关卡详情显示，未列出的配置沿用公共规则。

### 3.2 收益与用途

- 金币来源为持续基础收入与击杀奖励；用于出兵、建塔、塔位扩建、升级和更换防御塔。
- 每个单位配置独立的金币与 EXP 奖励。初步按其标准生产费用的 20% 与 30% 向下取整计算，奖励不受实际退款、关卡折扣或击杀方式影响。
- 单位、塔或技能击杀的奖励均归所属一方；每个死亡实体只结算一次。支援、受击、取消生产、出售塔和攻击基地不额外产生收益，防止重复刷取。
- EXP 为本局累计经验，只增不减；进化检查累计阈值，不扣除 EXP。金币与 EXP 分开，进化不额外收费。
- PvP 双方使用相同经济；经典 AI 也遵守相同资源约束。战役特殊收入加成在关卡表公开。

基础收入保证无兵可用时仍能恢复出兵，较低的击杀金币回收比例限制滚雪球；是否达到预期需用实战数据验证。

## 4. 五时代进化

| ID | 时代 | 主要风格 | 到达该时代的累计 EXP 初值 | 费用系数初值 |
|---|---|---|---:|---:|
| age1 | 原始时代 | 石器、兽皮、兽骑、部落图腾 | 0 | 1.00 |
| age2 | 古典文明时代 | 剑盾、长弓、枪阵、战车 | 300 | 1.20 |
| age3 | 火药时代 | 刺刀、火枪、火炮、军旗 | 900 | 1.45 |
| age4 | 现代战争时代 | 自动武器、精确射击、履带车辆 | 1800 | 1.75 |
| age5 | 未来科技时代 | 动力装甲、能量武器、机甲 | 3000 | 2.10 |

1. 达到下一时代阈值后，进化按钮亮起；玩家主动点击，每次仅提升一个时代。战役设置的最高时代构成额外限制。
2. 进化生效时更换基地外观、兵种菜单和可建造防御目录，当前时代六种兵**全部可用**。不依赖账号等级、战役通关或付费，也无额外局内研究。
3. 战场旧单位保留原属性；已付款队列保持原兵种、生产时间与顺序。菜单不再接受新旧时代兵种混选，只能新购当前时代单位。
4. 已建塔保留原时代和等级；玩家可花金币更换。技能替换为新时代版本，保留剩余冷却，不能利用进化刷新技能。
5. 战斗与生产不中断；不恢复基地 HP、不清场、不重置金币或 EXP。达到最高时代后显示“已达最高时代”。
6. 进化与出兵同时提交时，按权威处理顺序执行；已成功入队的旧兵保留，进化后才到达的旧时代出兵请求拒绝且不扣费。

新时代提供更高的整体属性预算与战术工具，但不得取消旧兵的克制价值。跨一时代的反重甲组合应仍可应对落单重甲；具体性能在混编测试中验证。

## 5. 兵种体系与 30 兵种矩阵

### 5.1 共同规则

近战、远程、重型是既有美术分类，不限制战术定位。六种兵应覆盖承伤、输出、反制、攻城、支援；同一兵种可以承担两个定位，但必须有明确弱点。

下表中“既有”表示保留原美术角色；“新增”表示本次扩展。轻甲、重甲、建筑是伤害结算类别，不直接等同于角色体型。生物、机械与动力装甲标签用于治疗或维修判定。

费用分低、中、高三档，原始时代试算基准分别为 70、110、200 金币，其他时代乘费用系数后向上取整。生产时间初值分别为 2、3、5 秒。下表给出档位和人口，HP、伤害、射程等在数值设计阶段逐项配置，不将这些费用当作最终平衡结果。

| age5_rail 磁轨炮手 | 新增；中 / 2 | 反重甲；轻甲 | 蓄力穿甲射击，命中同一直线上最多两名敌兵 | 对重甲阵列有效 | 装填慢，怕轻兵群 | 动力装甲兵、等离子射手 |
| age5_siege 攻城机甲 | 新增；高 / 3 | 专职攻城；重甲 | 展开后发射攻城能量炮 | 高基地伤害 | 展开慢，对兵效率低 | 动力装甲兵、维修机兵 |
| age5_support 维修机兵 | 新增；中 / 1 | 维修支援；轻甲 | 无普攻，维修一名机械或带动力装甲标签的友军 | 维持机甲与装甲推进 | 不修基地和塔，不恢复护盾，无法治疗普通生物兵 | 攻城机甲、动力装甲兵 |

攻城机甲与维修机兵为机械；其余为生物并带动力装甲标签。能量剑士首击强化每次出场一次；动力装甲兵护盾初值为最大 HP 的 20%，吸收结算后伤害。

### 5.7 支援与混编约束

- 支援单位不攻击基地或敌军；无有效对象时跟随最近的前方友军，保持支援距离，没有友军则向敌方推进，遇敌停步承伤，不越过敌军。
- 治疗优先选择有效范围内 HP 比例最低的目标，同值选距离最近者，再按实体 ID 排序；禁止治疗自身。目标死亡或离开范围则取消本次尚未生效的治疗并重新选取，不复活、不转移已生效的治疗。
- 同名光环只取最高强度，来源死亡或离开范围即失效。不同光环可并存；同一目标同一时刻的同类治疗只取最大效果，避免支援堆叠形成无限恢复。
- 医疗只恢复生物 HP，维修只作用于机械或动力装甲标签；均不能超过最大 HP，不能恢复基地、防御塔或一次性护盾。
- 支援效果可作用于符合标签的旧时代单位。支援人口计入上限，其价值要通过“同等费用的纯战斗兵 vs 混编”验证。

## 6. 出兵、队列与人口

点击兵种卡片后，依次检查：对局进行中、请求兵种属于当前时代、金币足够、队列未满、人口可预留。全部通过后一次性扣费、预留人口并入队；失败显示具体原因，金币和队列不变。

- 每方一条先进先出的生产队列，最多 5 项，包含正在生产的首项；生产完成后才生成实体，下一项开始计时。
- 占用人口 = 存活单位人口＋队列预留人口，不能超过 30；单位出生只将预留转成存活人口，不重复占用。死亡或取消队列释放对应人口。
- 等待项可取消并全额退款；正在生产项可取消，返还实付费用的 75%（向下取整），已耗生产时间不保留。单位出生后不能回收。
- 升级时代不清空队列；退出、投降或结算后停止生产，不将本局剩余资源带到下一局。
- 连续点击逐笔验证；失效请求不能造成负金币或重复单位。PvP 由服务端确认，按钮显示等待确认状态，重复请求按指令 ID 去重。

## 7. 自动战斗、护甲与克制

### 7.1 行为与目标

```text
出生 → 行进 → 检测有效目标 → 停步 → 攻击 / 支援前摇 → 效果生效 → 冷却
          ↑                     │                                  │
          └──── 无目标继续行进 ──┴──── 目标失效则重新选择 ────────────┘
```

普通单位选攻击范围内距离最近的敌兵，距离相同按实体 ID 排序。远程攻击不被友军阻挡；精确射手按第 5 节的支援优先规则，磁轨炮手按距离排列穿透目标。目标仍有效时保持锁定，避免无意义切换。

基地进入射程且攻击者与基地之间无敌兵时，才可攻击基地；范围普攻也只有在满足此条件时才对基地造成伤害。攻城单位也遵守这一条件，不从己方基地远程偷拆。防御塔不能成为独立攻击目标。

攻击前摇中目标死亡则重新索敌；已发射单体弹丸在原目标死亡时失效，不自动转向。范围弹丸飞向原落点，在命中时选择范围内有效敌人；无友伤，每个实体每次爆炸仅受一次伤害。穿透弹只打配置数量的敌兵，不顺带穿透攻击基地。

### 7.2 护甲结算初值

| 伤害类型 | 轻甲 | 重甲 | 建筑 |
|---|---:|---:|---:|
| 普通 | 1.00 | 0.65 | 0.50 |
| 穿甲 | 0.80 | 1.40 | 0.70 |
| 爆破 | 1.20 | 0.70 | 0.80 |
| 攻城 | 0.65 | 0.80 | 1.80 |
| 能量 | 1.00 | 0.90 | 0.60 |

基础伤害 × 护甲倍率 × 明确标注的单位特性倍率，再扣减护盾或 HP，计算后统一取整，伤害最小为 1。默认无暴击、闪避或随机命中。塔和技能也配置伤害类型；“远程”不自动等于穿甲。

克制依赖费用、射程、数量和前排保护共同成立，不保证某兵种一对一必胜。例如穿甲兵克重甲但怕廉价兵群，爆破克兵群但怕重甲，攻城克基地但依赖前排，支援提升持续作战但可被点杀。

## 8. 防御塔与时代技能

### 8.1 防御塔

基地最多 3 个塔位，初始开放 1 个空塔位。后两格用金币解锁，初值分别为 200、350，解锁后跨时代保留。塔不占人口、不进入兵种生产队列，也不提供独立 HP。

| 时代 | 单体塔：偏向持续输出或反重甲 | 范围塔：偏向兵群 |
|---|---|---|
| 原始时代 | 骨矛塔：穿甲 | 投石塔：爆破 |
| 古典文明时代 | 重弩塔：穿甲 | 火油塔：爆破 |
| 火药时代 | 连发枪塔：普通 | 榴弹塔：爆破 |
| 现代战争时代 | 反装甲导弹塔：穿甲 | 机枪阵列：普通范围伤害 |
| 未来科技时代 | 磁轨塔：穿甲 | 等离子塔：能量范围伤害 |

- 两类塔基础价格初值为 180、240，乘时代费用系数。每座有两级，升到二级支付基础价格的 60%，伤害初值提高 25%，射程不变。
- 建造、升级或出售由权威逻辑确认后生效；操作动画不暂停战斗。出售返还该塔累计实付费用的 50%，向下取整；不返还塔位费。
- 更换需先出售再建造，不能自动补差升级为新时代塔；旧塔跨时代保留。满塔位或金币不足时不扣费。
- 塔优先攻击射程内最近敌兵，不攻击敌方基地。射程必须小于战场长度的一半，避免双方纯塔互攻；基地被摧毁时塔同步停火。

### 8.2 时代技能

每时代一个主动范围技能，独立于单位支援技能。点击技能按钮进入落点选择，再点战场确认，取消不进入冷却。允许选择战场内任意位置，战场边界外的落点拒绝。首版共同基础冷却为 60 秒，公共预警为 1 秒，持续效果和伤害为待测配置。

| 时代 | 技能 | 行为与用途 |
|---|---|---|
| 原始时代 | 落石冲击 | 指定范围一次爆破伤害，打击密集兵群 |
| 古典文明时代 | 箭雨覆盖 | 指定范围分三次普通伤害，压制持续通过的轻兵 |
| 火药时代 | 炮火轰击 | 指定范围一次爆破伤害，惩罚聚集的远程阵地 |
| 现代战争时代 | 定点空袭 | 指定范围一次穿甲伤害，削弱重装推进；飞机仅为演出 |
| 未来科技时代 | 电磁震荡 | 指定范围一次能量伤害并短暂减速，创造补线时间 |

技能只影响敌方单位，不伤基地或塔，不造成友伤，不直接生成金币。击杀奖励依照公共规则。所有技能预警对双方可见；不允许静默瞬发。

技能确认成功即进入冷却，空放也消耗。已经施放的技能保持施放时版本，时代进化只改变下次可施放版本，剩余冷却原样继承。电磁减速初值 30%、持续 3 秒，同类减速取最大值，不叠成定身。

## 9. PvE：经典对战与战役

### 9.1 经典对战

AI 从金币、时代、队列、人口、可见敌军组成、战线、塔位、基地 HP 和技能状态生成合法行动，再按权重选择。无合法行动时等待基础收入。战役策略改变权重，不绕过扣费、人口、冷却和进化限制。

### 9.3 进度与结算

保存关卡解锁、已通关、最佳通关时间和最佳剩余基地 HP 比例；生存关的最佳时间只比较提前摧毁敌基地的记录。失败或平局不解锁下一关，不覆盖更好的成绩。

这些记录用于回顾和挑战，不提供 PvP 属性、金币或科技优势。首版先保存本设备 PvE 进度；账号云同步列入后续扩展，不能在界面承诺跨设备恢复。重复结算同一局只更新一次记录。

## 10. PvP：在线实时 1v1

### 10.1 公平规则

匹配与好友房均采用相同标准规则：原始时代开局、同金币与 EXP、同基地 HP、每时代六兵全开放、相同塔和技能、15 分钟上限。没有卡组限制，不继承 PvE 关卡加成、局外战力或解锁进度。

首版不提供排位积分或房主自定义属性。好友房只是邀请入口，不允许房主获得战斗控制权。匹配找不到真人时提示继续等待、取消或前往 PvE，不用 AI 冒充玩家。

### 10.2 匹配与好友房流程

1. 真人匹配：进入搜索，可随时取消；服务器配对成功后进入准备页。取消与配对同时发生时，以服务端确认状态为准，不能同时进入两个对局。
2. 好友房：创建后展示房间码和分享入口；好友输入房间码或点击微信小游戏分享卡片加入。只允许两位玩家，已满、过期、已开战分别显示原因。
3. 房间初值 10 分钟无人操作后过期；未开战时房主离开则关闭房间，另一人返回大厅。分享卡片只用于定位房间，入房与席位仍由服务端确认。
4. 两位玩家均载入资源并点准备后，服务端统一发出 3 秒开战倒计时。匹配准备超时初值 30 秒则取消本次配对；好友房可等待至房间过期。
5. 倒计时前可取消准备；倒计时中有人退出或断线，取消倒计时并返回准备状态，不判比赛负。开战后主动退出须确认投降，其他断线按重连规则处理。
6. 每位玩家最多一个进行中的 PvP 对局，重新进入小游戏优先恢复该局或显示其结算，不能另开一局规避结果。

### 10.3 权威裁决与异常

客户端提交出兵、取消队列、建塔、升级、出售、进化、技能和投降意图；**服务端权威维护**资源、生产、移动、伤害、冷却、时钟及胜负。客户端表现与预览不能直接产生伤害或奖励。

- 每局固定配置版本；资源或版本不匹配的客户端停留在准备页并提示更新，不进入不同规则的比赛。
- 指令检查身份、对局状态、资源与合法目标；重复提交同一个指令 ID 返回已有结果，不重复扣费。结算按对局 ID 唯一生成，重试只查询原结果。
- 网络中断期间战斗继续，已确认的队列、塔和自动战斗继续执行；不生成新指令，也不交给 AI 接管。未确认的操作显示状态未知，恢复后按权威记录核对。
- 自服务端确认连接失效起保留 **60 秒**重连机会。重连成功恢复当前快照、队列、金币、时代和剩余时间，不补算离线点击、不重放已执行指令。
- 60 秒到期未恢复连接的一方判负；若两方同一裁决时刻都达到断线超时，则平局，否则先超时者负。对局已因基地摧毁等结束时，重连只展示原结算。
- 小游戏切后台不暂停 PvP；返回前台先同步再开放按钮。若后台连接失效，使用同一套 60 秒规则，不额外给予暂停时间。
- 确認为服务端故障且无法可靠恢复的对局标记“无效”，双方无胜负记录；客户端单方报告卡顿不能自行将比赛作废。

### 10.4 对局节奏与结算

标准对局上限为 **15 分钟**，目标体验时长为 8～12 分钟，目标需实测验证。倒计时和重连时间都以服务端为准。

结算显示胜／负／平／无效、结束原因、时长、双方最高时代、生产与击杀数量、基地剩余 HP 比例。匹配局提供“再次匹配／返回首页”；好友局双方同意后创建新一局并重新准备，离开则返回首页。

## 11. 微信小游戏页面与操作

### 11.1 页面设计

发行位置统一为微信小游戏，首页、模式页、战役页、房间页、战斗页和结算页都围绕小游戏内体验设计。采用 game.js + game.json 的 Canvas 场景，首页、战斗和结算统一横屏；窗口尺寸变化只调整显示和触控映射，不重置对局。

战斗区域预留微信右上角胶囊与设备安全区域。长按兵种显示详情，短按购买；详情面板在 PvP 不暂停。兵种卡固定分为 A、B 两组三张，A 为既有三兵，B 为新增三兵，通过显式分页按钮切换。

```text
┌──────────────────────────────────────────────────────────────┐
│ 我方 HP / 敌方 HP    金币 520    EXP 210/300    时代 / 时间     │
│ 人口 12+3/30（存活+预留）                 网络状态 / 安全区   │
│                                                              │
│ 我方基地与塔 → 我军 → 战斗区域 ← 敌军 ← 敌方基地与塔           │
│                                                              │
│ 队列：[生产中 1.2s][等待][等待][空][空]                        │
├──────────────────────────────────────────────────────────────┤
│ [兵1][兵2][兵3] [A/B切换]  [防御塔] [技能 35s] [进化] [菜单] │
└──────────────────────────────────────────────────────────────┘
```

- 卡片显示名称、图标、价格、人口；详情显示定位、护甲、目标、攻击／支援方式、强弱项、生产时间与关键数值。
- 图鉴显示全 30 种兵；战斗菜单只显示当前时代六种，翻页不影响队列。进化后回到 A 组并短暂提示新增时代内容。
- 固定区域保留防御、技能和进化；不足金币、人口已满、队列已满、冷却中、等待确认分别呈现明确状态。
- 点击队列项查看取消与退款；技能落点选择提供取消按钮；进入菜单时 PvP 继续计时并显示“对局继续进行”。
- 阵营以颜色加徽记区分，不能只依赖红绿；文字、数值、冷却和状态标记由界面绘制，不烘焙进头像。

### 11.2 小游戏前后台与分享

PvE 主动暂停或小游戏进入后台时暂停双方模拟，保存本局快照；返回前台显示继续／退出。被系统回收后仅在存在完整且版本匹配的本地快照时恢复，否则提示本局无法恢复并提供重新挑战，不写入虚假胜负。

PvP 没有本地暂停或离线续战。返回小游戏时恢复服务端会话、查询对局状态，先显示同步中，再进入当前战场或已完成结算。网络不可用时仍可进入已具备资源的 PvE。

好友房使用小游戏分享卡片引导进入房间；分享由玩家主动触发，分享失败仍可使用房间码，不把“分享成功”作为开战或奖励条件。微信官方维护的 [小游戏 API 类型定义](https://github.com/wechat-miniprogram/minigame-api-typings)可核对wx.onShow／wx.onHide 和分享 API；查阅日期 2026-09-28。具体基础库兼容性、横屏切换与联机能力须在小游戏真机原型阶段验证，不在本玩法文档承诺后台持续执行。

## 12. 胜负裁决与完整玩家流程

### 12.1 统一结束顺序

一次权威逻辑步先汇总双方伤害并更新基地 HP，再裁决胜负，不能因为先处理左侧伤害而让右侧丢失同时命中的机会。

| 顺序 | 条件 | 结果 |
|---|---|---|
| 1 | 已确认服务端故障且无法恢复可靠状态（PvP） | 无效，不记胜负 |
| 2 | 双方基地在同一逻辑步归零 | 平局；战役不通关 |
| 3 | 一方基地归零 | 该方负，对方胜 |
| 4 | 投降或 PvP 断线超时 | 该方负；双方同一步触发则平局 |
| 5 | 战役生存目标到时且我方基地存活 | 胜利 |
| 6 | 达到对局时限 | PvP／经典对战比较基地 HP 比例；战役摧毁型关卡失败 |

HP 比例为当前 HP／开局最大 HP，用未四舍五入的值比较；相等平局，不加时。同一步出现基地归零与到时或投降，优先使用基地结果。只执行首个适用裁决，结果一旦生成即冻结战斗，不重复发奖或改变结局。

### 12.2 PvE 完整流程

进入小游戏 → 选择经典难度或战役关卡 → 阅读目标和敌情 → 原始或关卡指定时代开局 → 查看全部六兵 → 前排配后排出兵 → 观察敌军并补充反制／支援 → 分配金币给塔与部队 → 使用技能 → EXP 达标时进化 → 继续保留旧兵混编 → 达成目标或失败 → 查看战报并更新通关记录 → 重试、下一关或首页。

### 12.3 PvP 完整流程

进入小游戏 → 真人匹配或好友房 → 双方资源载入、准备 → 统一倒计时 → 公平开局 → 出兵试探与反制 → 防御投资／进化时机博弈 → 攻城推进 → 基地结果、投降、断线超时或 15 分钟裁决 → 服务端生成唯一战报 → 再次匹配、好友再战或首页。

## 13. 配置字段与职责边界

本节仅定义后续数据设计所需的字段和职责，不规定语言、存储方案、序列化格式或网络协议。ID 稳定，显示名可改；运行中的对局固定引用配置版本。

| 数据类别 | 必要字段组 | 职责 |
|---|---|---|
| 时代配置 | 时代 ID、显示名、顺序、累计 EXP 阈值、费用系数、六个单位 ID、塔目录、技能 ID、基地外观 | 定义进化内容和目录 |
| 单位配置 | 单位 ID、时代、角色／护甲／生物机械标签、HP、伤害、攻击间隔、前摇、射程、移动速度、范围／穿透、目标规则、费用、生产时间、人口、金币与 EXP 奖励、支援／特性参数、资源键 | 驱动战斗与图鉴；属性不能只写在美术名称里 |
| 塔与技能配置 | ID、时代、目标、伤害类型、射程／范围、价格、等级、冷却、预警、持续时间、效果参数、资源键 | 共用自动攻击和范围效果规则 |
| 模式配置 | 模式 ID、开始／最高时代、初始资源与基地 HP、收入、队列／人口、时限、结束方式、暂停策略、重连窗口、AI 档位 | 区分 PvE、PvP 与战役覆盖项 |
| 关卡配置 | 关卡 ID、前置关、教学目标、时代范围、胜负目标、时限、AI 权重、公开初始配置与加成 | 生成选关信息和实际关卡，展示与运行同源 |
| 战斗状态 | 对局 ID、配置版本、模拟时间、双方时代／金币／EXP／HP、实体与位置、队列与预留人口、塔位、技能冷却、连接状态 | 支持暂停、重连和状态复核 |
| 战斗指令 | 对局 ID、玩家 ID、指令 ID、操作类型、目标／参数、处理状态 | 表达意图，权威逻辑验证和去重；客户端不上传最终伤害 |
| 结算与进度 | 对局 ID、模式／关卡、结果与原因、时长、双方统计、基地 HP 比例、配置版本、结算状态；关卡解锁与最佳记录 | 唯一结算、回顾与 PvE 进度更新 |

## 14. 开发阶段与验收场景

具体设计输入、产出与依赖见 [设计流程](design-process.md)。内部原型的内容规模不等于最终首版交付范围。

| 阶段 | 产出 | 完成标准 |
|---|---|---|
| 单时代核心原型 | 原始时代六兵、资源、队列、人口、自动战斗、基地、塔和技能 | 可完成一局，六兵定位成立，经济不会永久停摆 |
| 五时代与 PvE | 30 兵、进化、三档 AI、15 关、暂停恢复、进度和结算 | 经典与战役流程完整，跨时代及支援规则正确 |
| 在线 PvP | 真人匹配、好友房、权威模拟、同步、重连、唯一结算 | 两台真机从开房到结算可完成，公平性与异常处理通过 |
| 首版联合验收 | 微信小游戏中的 PvE＋PvP 完整体验、统一美术与 UI | 两种模式均可用，不能把 PvP 推迟后仍称首版完成 |

| 场景 | 预期行为 |
|---|---|
| 金币不足、队列满、人口满、连点出兵 | 拒绝非法请求且不扣费；出生不重复计人口 |
| 进化时旧兵仍在生产；同一步提交旧兵和进化 | 已确认队列保留；后到的过期兵种请求拒绝 |
| 旧时代穿甲兵对新时代重甲，带旧支援混编 | 沿用各自属性和克制，不因时代差免疫或自动升级 |
| 治疗目标死亡／离开范围，同名光环重叠 | 重选目标、不复活；光环不叠加，失去来源即结束 |
| 塔位满、更换旧塔、进化中技能冷却 | 不越过金币与塔位限制；技能不被刷新 |
| 单体弹丸目标先死、范围攻击空落点 | 不自动转向或凭空奖励；范围按实际命中结算 |
| 两基地同一步归零；到时恰逢基地被毁 | 平局；单方被毁时基地结果优先 |
| 战役失败、通关、重玩、重复结算 | 只在胜利时解锁下一关，最佳记录和更新不重复 |
| 匹配取消与配对竞争，房间已满或过期 | 返回唯一有效状态，不创建重复对局 |
| PvP 重连成功、60 秒超时、结算后重连 | 恢复权威快照；超时判负；已结束则展示原结果 |
| 双方同时掉线、服务端不可恢复、重复指令 | 按统一顺序判定；服务故障无效；只执行一次 |
| 小游戏分享入房、横屏、安全区、前后台切换 | 页面与触控可用；PvE 暂停，PvP 持续并同步恢复 |

当前文档验收只确认规则完整性、一致性及来源可追溯。对局时长、胜率、单位强度、真机帧率与网络体验必须在后续原型和联调中实测。
